# 桌面客户端接入与发布记录

## 目标与实施方案

1. 统一工作区身份，将所有软件新建任务绑定名称“小说”及 `D:\小说` 根目录，同时核对客户端项目编号和桌面侧栏归属。
2. 为前端加入执行类型、模型和思考等级选择。模型与支持的思考等级由各客户端实际返回，按客户端保存选择。
3. Antigravity 通过本地语言服务创建会话，先校验项目，再设置 Turbo 权限，然后发送完整多行任务。
4. Codex 通过安装程序提供的 app-server 查询模型，通过桌面本地接口创建项目聊天并继续实际任务。创建前核验本地完全访问，实际任务启动后检查模型、思考等级和权限执行记录。
5. 云端验证所选类型、模型、思考等级及工作区。任务携带完整执行参数，本地再次校验，完成后读取成果回执再同步。
6. 保留文件存储和现有 Redis 缓存架构。隔离测试通过后备份、提交推送、部署、重启桥接器，核对生产任务、数据摘要与 APK。

## 桌面兼容处理

当前 Codex 桌面版本为 `26.1106.6628.0`，内置执行程序为 `0.167.0-alpha.4.1`。app-server 的项目编号与桌面侧栏使用的项目编号不同，软件分别查询并核对根目录。

实际测试发现新建接口对模型的校验与模型目录返回存在差异。接入流程先在目标项目创建仅回复“初始化完成”的聊天，等待完成及侧栏归属确认，再通过桌面继续聊天接口发送实际任务与明确的模型、思考等级。实际任务执行上下文必须匹配选择，并具备 `approval_policy=never` 和 `sandbox_policy=danger-full-access`。每个 Codex 任务因此增加一轮初始化，初始化使用桌面默认模型。

桌面本地接口随安装版本变化。接口、工作区、模型或权限校验失败时，软件显示具体失败原因。Antigravity 支持的 Gemini 思考档位对应独立模型变体，Claude 等模型按客户端提供的内置思考模式显示。
