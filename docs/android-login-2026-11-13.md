# Android 首次登录与七天缓存修复

## 问题与原因

用户安装 1.9.0 后，客户端显示“请登录后重试”，章节、设定与模型停留在加载状态。网页登录依赖 JavaScript prompt，Android 外壳缺少 WebChromeClient，首次登录无法取得口令输入。此前浏览器测试预置了令牌，未覆盖首次安装登录。

## 修复

- 页面内提供可见的口令表单，首次启动自动显示。错误口令和网络错误在表单内显示并允许重试，成功后继续加载原请求。
- 并发 401 请求共用同一登录流程。网络超时只覆盖实际网络请求，用户输入口令期间可以正常停留。
- 登录成功后在设备保存七天有效登录凭据，服务端使用签名和过期时间校验。凭据在服务器重启后仍可校验。本机缓存按有效时长计时，兼容设备与服务器的时钟差。桥接器继续使用私有独立桥接令牌。
- 旧版已保存登录信息在首次使用修复页面时迁移到七天本地有效期。新登录签发独立的七天凭据。
- 过期后自动重新显示登录表单。正文、模型与设定的加载失败显示原因与重试入口，移除启动时虚构的 11 章、5.2 万字、98 分。
- HTML 入口使用 no-store。Android 1.9.1 / versionCode 12 增加 WebChromeClient，登录凭据通过 WebView 本地存储和七天 Cookie 保存，沿用既有签名。

## 验证

- 70 项 Python 回归通过，新增七天精确过期边界、Cookie 认证、签名篡改拒绝、随机登录凭据和 HTML 缓存策略。
- Chrome 隔离上下文使用 Android WebView 1.9.0 UserAgent，并使 native prompt 不可用。验证首次登录表单、错误口令后重试、13 章与 7 份设定加载、模型目录、四图画廊及 390px 布局。
- 失效令牌触发的并发 401 共用表单，停留 21 秒后仍能登录，刷新页面保持登录，模拟本地有效期到期后重新登录成功。
- 原有阅读、文案保存与复制、下载、多书切换、草稿、模型与思考等级选择回归通过。

## 验收范围

浏览器测试覆盖未登录与过期恢复。实体 Android 手机安装升级和系统 WebView 的实际表现仍需在用户设备确认。
