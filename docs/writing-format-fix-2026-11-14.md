# 1.11.1 续写记忆格式修复

## 实际故障

手机下发的7章续写任务在第一份资料提取后停止，完成0/7章。Agent返回合法JSON，人物状态使用包含身份、位置、能力等字段的对象。提示词未明确人物映射值的类型，程序仅接受字符串，导致“人物状态格式无效”。此前模拟返回使用字符串，未覆盖这类真实输出。

## 修复

- 人物状态允许字符串、对象和数组，结构化内容完整序列化保存，保留原有事实和字段。
- 提示词提供完整JSON示例，明确无变化时的空对象、空数组，以及仅返回当前片段更新，避免重复全员小传。
- 原始提取结果在校验前落盘，由资料内容链确定缓存键。格式异常时使用原结果进行一次JSON修复，持续不合法时保留两份结果并停止。
- 复用本次已经完成的提取结果，核对原始文件后继续后续步骤。
- 阶段提示词明确输入已完整附带、父目录已创建，限定本阶段结果与新回执的文件访问，直接写入并校验本次两份文件，减少对旧暂存文件和旧回执的重复扫描。
- 手机刷新后自动关联当前作品的运行中任务，保留进度查看能力。状态标题显示实际准备、写作或审核阶段。切书清除旧轮询与显示，并拒绝旧异步回复覆盖当前作品。

## 验证

本地168项回归测试通过，增加真实返回形态、嵌套字段保留、缓存复用、格式修复次数与持续失败检查。实际失败结果已离线通过兼容校验，包含10名人物的结构化状态，转换后7275字符。

实际作品还包含55,728字符的长篇分章细纲。修复后设定建立本地索引，作为规则与规划来源保留，未来规划不覆盖当前已发生的人物状态。当前章节细纲按条目读取，其他长设定按相关段落引用，历史正文按所引用的章节完整读取。正文记忆每批最多3片、最多15,000原文字符，在每个来源上保留独立内容链检查点，减少反复创建会话。

实际41份资料的隔离副本完成整轮写作规模演练，包含结构化人物状态、长细纲与历史回溯，最大请求55,152字符，记忆批次20次。该演练使用模拟上游，真实模型的最终验收记录见1.11.2流程记录。
