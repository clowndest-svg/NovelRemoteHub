# 多章续写与连贯性处理

自动续写入口新增同款 select-box 下拉框，可选 1–10 章，默认 1 章。精修、大纲与自由指令使用各自的原有工作流。任务携带 chapter_count，云端与本地校验整数和范围。

## 执行流程

每轮从实际章节文件重新计算下一章编号，重新读取最新前章、对应分章细纲与设定清单。任务明确要求通读前章全文，核对时间线、人物位置和认知、能力限制、伤势及伏笔，检查前章结尾到本章开头的因果衔接。每轮只新增当前章，写完后读取成果回执，校验新增文件唯一、章号正确、内容非空及历史正文内容一致，再同步并进入下一轮。

每章单独创建所选客户端的小说项目会话，模型、思考等级及权限沿用任务选择。进度显示已完成章数。模型失败、文件异常、历史正文变化或同步失败时停止后续章节，并保留已完成结果供核对。任务重试从现有最新章节计算后续章号。

## 验证

- 78 项自动回归通过，新增数量范围、模式限制、逐章上下文更新、半途失败、缺失成果、历史正文变化和同步失败停止的检查。
- 实测发现模型手工拼接回执中的引号可能导致无效 JSON，已要求使用序列化 API 写入并解析回读。补充 UTF-8 BOM 兼容及终止状态下无效 JSON 的明确失败处理。
- Codex 在隔离作品中实际连续生成第 002、003 章。第 002 章进入旧亭、保留右手伤势并遵守天亮前不开匣，第 003 章承接刻痕和伤势，天亮后由同行者开匣并发现残图。原第 001 章校验一致。此测试的云同步使用隔离桩，生产正文由摘要复核保护。
- Chrome 检查下拉数量、模式切换、请求透传、360/390/768/1440 宽度、配色及运行错误。原有阅读、素材、登录和模型选择回归通过。

AI 执行中的逻辑检查依赖模型阅读和创作能力，程序验证成果文件、章号、历史正文与同步状态。

## 排队与回执停滞修复

实际任务中发现前序十章任务执行到第 23 章时，agent 仅在聊天回复正文而未保存文件或回执，导致后续三章任务排队。已在原会话补齐保存，原队列恢复推进。

任务查询新增前方任务数量、前序任务最新进度，界面明确显示排队和实际接收状态，以及轮到时按最新章节衔接。Agent 结束回复且缺少回执时，等待短暂落盘窗口后在原会话补齐原任务的文件与回执，自动补齐限一次，再次缺失时明确失败结束等待。81 项回归通过，覆盖队列进度、补齐成功和补齐次数边界。

## 连续任务幂等保护

同一请求编号的重试返回原任务，编号与请求内容冲突时拒绝。相同作品、正文要求、模型、思考等级与章数的未完成续写任务合并到已有任务。不同章数或要求保留独立队列位置。

前端在发送前持久保存本次请求编号，网络失败、刷新后重试沿用编号，收到明确成功响应后清除重试记录。每轮写作时从当前文件重新计算章号。回归覆盖从第 20 章开始完成十章后，再执行三章时从第 30 章开始至第 32 章，以及并发重试只创建一个任务。85 项回归与浏览器网络失败/刷新重试测试通过。
